## MODE_CUBEMARS デバイス (root_theta_joint / tip_theta_joint用)
device_id (ros2can GUIのデバイス一覧に出る番号、= このボード自身のCAN_ID):
  →11

各M{n}スロット(config.hppのCUBEMARS_MOTOR_ID_n、デフォルト101/102/103/104)が
実際にどの関節のCubeMarsモータに配線されているか:
  M1 (デフォルトCAN_ID=101) → 対応関節:根本θ
  M2 (デフォルトCAN_ID=102) → 対応関節:手先θ
  M3 (デフォルトCAN_ID=103) → 対応関節:未使用
  M4 (デフォルトCAN_ID=104) → 対応関節:未使用

## MODE_ROBOMAS デバイス (motor1_joint / motor2_joint用)
device_id (ros2can GUIのデバイス一覧に出る番号、= このボード自身のCAN_ID):
  →　21

各M{n}スロットが実際にどちらのロボマスモータ(motor1/motor2)に対応するか
(CAN_ID自体はC610本体のID設定スイッチで決まり、0x201=M1, 0x202=M2, ...):
  M1 (CAN_ID=0x201) → 対応: motor1_joint
  M2 (CAN_ID=0x202) → 対応: motor2_joint
  M3 (CAN_ID=0x203) → 対応: 未使用
  M4 (CAN_ID=0x204) → 対応: 未使用

## 外付けAMTエンコーダ (ENC1/ENC2、z_joint/r_joint用、ROBOMASのCAN帰還とは別物)
**2026-08-31時点で不使用(方針変更、note/hardware_mapping.txt参照)**: z_joint/
r_jointの位置真値はROBOMAS内蔵ロータエンコーダのCAN帰還(M{n} angle)に統一され、
このENC1/ENC2は使わなくなった。配線情報は記録として以下に残す。
MODE_ROBOMASのM{n} angleはC610/M2006内蔵ロータエンコーダのCAN帰還値であり、
これとは別に外付けAMTエンコーダが存在する場合、device_profiles.pyの
ENC1/ENC2チャンネル(MODE_CAN/MODE_CAN_HOST/MODE_IOの汎用IOノード側)経由に
なるはず。以下を記入:

device_id (このENC1/ENC2を持つCAN_HOSTボードの番号):
  → 101
  ※ENC1/ENC2はCAN_HOST自身の直下スロットではなく、配下の「ノード」の
    ローカルスロット(帰還: 0=SW1,1=SW2,2=SW3,3=ENC1,4=ENC2、
    device_profiles.py _append_generic_io_node_channels参照)。
    グローバルスロット index = node_index*slots_per_node(既定5) + local_index
    (例: node_index=0なら ENC1=slot3, ENC2=slot4。node_index=1ならENC1=slot8, ENC2=slot9)

node_index (ENC1/ENC2がぶら下がっているノード番号、0-origin。
ros2can GUIの当該ノード欄の「N{node_no}」表示で確認、node_no = node_index+1):
  → 1

ENC1/ENC2はそれぞれ何を測っているか(どちらか一方に◯、または直接記述):
  (o) motor1_joint/motor2_joint軸(差動ミキシング前、モータ/プーリ軸の回転)
  (x) z_joint/r_joint軸そのもの(ミキシング後、直動部に直接取付、リニアor別ロータリー)

  ENC1 → 対応軸:motor1_joint
  ENC2 → 対応軸:motor2_joint

エンコーダ分解能(1回転あたりのカウント数、CPR/PPR。AMT系はDIPスイッチ設定値):
  →2048

(1カウントあたりの移動量、またはエンコーダ分解能とねじリード/プーリ径等の元情報):
