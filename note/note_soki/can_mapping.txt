## z/r上限リミットスイッチ (過走防止の安全停止用、trajectory_follower_node) 2026-08-31追加
上記の原点センサ(下限側、homing_node用)とは別に、反対側(上限側)にもz軸・r軸
それぞれ1個ずつセンサがある。trajectory_follower_nodeがこれらを直接監視し、
トリガーされている方向への移動だけをロックする(反対方向への後退は許可)。
soki_sim/config/real_joint_bridge.yamlのtrajectory_follower_node:セクションに
これらのパラメータ(*_device_id/*_node_index/*_local_index、device_id=0で無効)
がある(既定は全て0=未配線)。command_gui_nodeの「z/r安全停止センサ配線設定」
パネルからも読込・編集・保存できる(他のyaml配線パネルと同様、次回
trajectory_follower_node起動から反映、実行中には反映されない)。下限側も
homing_nodeとは別パラメータとしてtrajectory_follower_node側に持たせているので、
安全停止を有効にするならそちらも合わせて設定する
(z_lower_limit_switch_*/r_lower_limit_switch_*)。

z軸上限センサ:
  z_upper_limit_switch_device_id →
  z_upper_limit_switch_node_index →
  z_upper_limit_switch_local_index(SW1=0/SW2=1/SW3=2) →

  r_upper_limit_switch_node_index →
  r_upper_limit_switch_local_index →

z軸下限センサ(trajectory_follower_node側、通常は上のz軸原点センサと同じ配線):
  z_lower_limit_switch_device_id →
  z_lower_limit_switch_node_index →
  z_lower_limit_switch_local_index →

  r_lower_limit_switch_device_id →
  r_lower_limit_switch_node_index →
  r_lower_limit_switch_local_index →

## ハンド (エンドエフェクタ、2026-09-03追加、2026-09-07一部確定)
tip_link(tip_theta_jointの先)に付く吸着ハンド。サーボ2個(吸着パッド展開・
ワークピッチ変更)とダイヤフラムポンプ1個(吸着源、MD経由50%デューティ)、
真空破壊リレー1個(2026-09-07追加、下記参照)で構成(note/claude.txt「##ハンド」
参照)。いずれもxiao-esp32-s3_can2io MODE_CAN_HOST配下の汎用IOノード
(SERVOx3/MDx2/SWx3/ENCx2、ピン共有あり。ros2can/ros2can/device_profiles.py
参照)を使う想定。

汎用IOノード1台分(can_host_slots_per_node=5)のローカルスロット並び
(ros2can/ros2can/device_profiles.py _append_generic_io_node_channels、
firmware frame_data.cpp参照): local0-2=SERVO1-3(SWnとピン共有)、
local3=MD1(ENC1とピン共有)、local4=MD2(ENC2とピン共有)。
**MD1/MD2はlocal_index 0/1ではなくlocal_index 3/4**(2026-09-07訂正:
以前このメモ自身がMD1=0/MD2=1と誤記していた)。

吸着パッド展開サーボ:
  device_id(このCAN_HOSTボードの番号) →
  node_index(ぶら下がっているノード番号、0-origin) →
  local_index(SERVO1=0/SERVO2=1/SERVO3=2) →
  角度範囲(収納時/展開時、それぞれ何度か) →

ワークピッチ変更サーボ:
  device_id →
  node_index →
  local_index(SERVO1=0/SERVO2=1/SERVO3=2) →
  角度範囲(保持時/シューティングボックス投入時、それぞれ何度か) →

ダイヤフラムポンプ(MD1、PWM+DIR出力、符号=方向・絶対値=デューティ。
DEFAULT_MD_PWM_MAX=255換算で50%運転 ≒ ±127):
  device_id → 101 (2026-09-07ユーザー確認: 「ダイヤフラムがCAN101のMD1に
    接続されているはず」。CAN_HOST device_id=101はhoming_nodeのz/r原点センサ
    (SW1/SW2)と同じボード、note/hardware_mapping.txt「CAN_HOSTデバイス」参照)
  node_index → 0 (ホスト自身=node0。z/r原点センサのSW1/SW2はnode_index=1の
    別ノード(STM32 b-g431-esc1_can2io)なので混同注意)
  local_index → 3 (MD1、上記スロット並び参照)
  ON/OFF方式 → 常時50%固定(duty=0でOFF)。soki_sim/config/hand.yaml
    pump_duty_percent参照

真空破壊リレー(MD2、2026-09-07新規): ワークを離す際に真空破壊が必要で、
そのためのリレーをMD2のDIRピンで代用する計画(ユーザー確認)。DIRピンは
`digitalWrite(MD2D, raw>0 ? HIGH : LOW)`のようにduty量とは無関係に符号だけで
決まる(firmware pin_ctrl_task.cpp IO_MD_Output参照、PWM出力自体はリレーに
配線しないので無視される)。独立サービスにはせず、ポンプON中はリレーOFF
(閉、真空保持)・ポンプOFF時はリレーON(開、真空破壊)と連動させる
(hand_node.py _on_pump_on/_on_pump_off/_set_vacuum_release参照)。
  device_id → 101 (ポンプと同じCAN_HOSTボード)
  node_index → 0
  local_index → 4 (MD2)

備考: SERVOn/SWnはピン共有、ENCn/MDnもピン共有のため、既存のz/r原点センサ
(SW1/SW2、node_index=1の別ノード)と物理配線が衝突しないよう要確認。
ENC1/ENC2は不使用となったため両方MD出力へ転用済み(config.hpp
ENC1_MD=1/ENC2_MD=1、note/hardware_mapping.txt「z_joint/r_jointの実機出力」
参照)。上記device_id/node_index/local_indexは実機配線からの申告ベースで
soki_sim/config/hand.yamlに反映済みだが、現物での最終確認はまだ。

## 状態表示灯 (黄色/赤色LED、2026-09-08追加)
CAN_HOST(device_id=101)自身のノード(node_index=0)のMULTI1/MULTI2に、状態表示用の
黄色LED・赤色LEDをそれぞれ追加接続(ユーザー確認)。マイコンのファームウェアは
書き込み済みだが、本リポジトリのros2can/generated_firmware/soki_host_101/src/
config.hppはMULTI1=0/MULTI2=0(スイッチ入力モード)のまま未反映(実機では
MULTI1=1/MULTI2=1のservo/PWM出力モードになっているはず、要確認)。

  MULTI1 → 黄色LED (注意系)
  MULTI2 → 赤色LED (異常系)

各色とも 消灯/点灯/点滅(速)/点滅(遅) の4パターンで状態を表現する(既存の
status_led.cpp、pin21の単色LEDが実装済みの「CAN活動中=100ms周期点滅/シリアルのみ
活動=短いパルス点滅/非活動=消灯」という3状態パターンを参考に拡張したもの)。
状態⇔パターンの対応(2026-09-08確定):

黄色LED(注意系。複数該当時は上の行を優先表示):
  点滅(速) → 自動シーケンス実行中(ピック/投入、hand_node)
  点滅(遅) → ホーミング実行中
  点灯     → 未ホーミング(起動直後の待機)
  消灯     → 通常(準備完了)

赤色LED(異常系。複数該当時は上の行を優先表示):
  点滅(速) → ソフト緊急停止押下中(2026-09-08訂正: 当初CAN Bus-Offを想定していたが、
              Bus-Off検知にはファームウェアのテレメトリ拡張が必要なため今回は
              スコープ外にし、代わりにソフト緊急停止に差し替えた。ユーザー指定)
  点滅(遅) → ノード未起動(想定しているノードが応答していない)
  点灯     → リミットスイッチによる安全停止中(trajectory_follower_nodeが移動ロック中)
  消灯     → 異常なし

備考: MULTI1/MULTI2はSERVO1/SW1、SERVO2/SW2とピン共有(config.hppのMULTIn設定で
切替)。上の「## ハンド」節でこの2ポートを吸着パッド展開/ワークピッチサーボに
使う可能性が「未確定」と記載されていたが、soki_sim/config/hand.yaml確認済み:
実際は deploy_servo_device_id/pitch_servo_device_id とも31(CAN_HOST device_id=
101とは別のボード)のため、この2ポートとの競合は無かった。

soki_simのGUI(command_gui_node.py)にも上記と同じ判定ロジックで黄・赤LEDの
シミュレート表示を実装済み(2026-09-08、実装内容の詳細はnote/claude.txt
「## soki_simのGUI実装」節参照)。ソフト緊急停止はGUI/joy_teleop_node(PSボタン)
双方から呼べ、単なる表示ではなくtrajectory_follower_nodeの実機/sim出力を
実際に凍結する。実機LEDへのCAN送信(serial_tx_101のslot0/1)はhand_node.pyが
担う(pump/vacuum_releaseと同じdevice_id=101のバッファを共有するため、
送信元を1つにまとめる必要があった。ファームウェアはsoki_host_led_101、
MULTI1/MULTI2=2のデジタル出力モードを使用。詳細はnote/claude.txt「## soki_sim
のGUI実装」節の「実機LEDへの送信」項参照)。
